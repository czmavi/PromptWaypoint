# macOS distribution

macOS is distributed directly from GitHub Releases. There is no Mac App Store,
TestFlight, provisioning profile or App Sandbox build. iOS distribution is
separate. The app bundle ID remains `com.caretsix.aiproductmanager`.

## Install and run

1. Download
   [Prompt-Waypoint.dmg](https://github.com/czmavi/prompt-waypoint-releases/releases/latest/download/Prompt-Waypoint.dmg).
2. Drag **Prompt Waypoint** to **Applications**, eject the disk image, then open
   it from Applications. The universal app supports Apple Silicon and Intel on
   macOS 13.3+.
3. In **Settings → Local Agent & Server**, choose **Start Local Agent** once.
   This also enables starting the agent whenever the app opens. No Deno
   installation or terminal command is needed. Codex CLI / Claude Code must
   still be installed and authenticated with their own tools.
4. Choose project folders and add discovered provider profiles in Settings.
   Enable **Launch at login** if desired.

Closing the window keeps the app and its agent in the menu bar. **Quit** stops
its bundled agent. The app reuses an authenticated, separately running agent
without taking ownership of that process. It never kills an unrelated listener.

The agent stores its database and local token in `~/.pmai-agent`. Cloud access
is optional; the existing server/device-token configuration still applies.
Provider credentials stay in the provider's own configuration directory. The app
adds common Homebrew, npm, nvm and VS Code Codex installation paths to the
agent's PATH; unusual CLI locations require configuring the launch environment.

## Updates

The app checks on opening and every six hours; **Check for updates** also runs a
manual check. **Update and restart** downloads and verifies the updater
signature, asks the owned agent to stop accepting work, flushes it and installs
the app. Both agent architectures update with the app. Running/dispatching
executions or uncertain execution state block installation. Stop or resolve them
first. Paused sessions survive in the agent database. A separately started agent
must be stopped manually before installing an update.

The public manifest endpoint is:

```text
https://github.com/czmavi/prompt-waypoint-releases/releases/latest/download/latest.json
```

The promo web links directly to the latest DMG. Neither download requires a
GitHub account. `latest.json` uses **versioned** archive URLs, so an in-progress
update cannot mix an old signature with a newly published archive.

## One-time GitHub / Apple setup

Create the public **`czmavi/prompt-waypoint-releases`** repository with a
README. Only release assets go there; source stays in the private `czmavi/pm.ai`
repository. The download links return 404 until the first release is published.

In the source repository, create a GitHub Actions environment named
**`macos-release`** and add these secrets:

| Secret                               | Value                                                                             |
| ------------------------------------ | --------------------------------------------------------------------------------- |
| `APPLE_SIGNING_IDENTITY`             | Full `Developer ID Application: … (TEAMID)` identity                              |
| `APPLE_CERTIFICATE`                  | Base64 of the exported Developer ID Application `.p12`, including its private key |
| `APPLE_CERTIFICATE_PASSWORD`         | Password of that `.p12`                                                           |
| `APPLE_API_KEY`                      | Apple App Store Connect API key ID, used only for notarization                    |
| `APPLE_API_ISSUER`                   | Issuer UUID of that team API key                                                  |
| `APPLE_API_PRIVATE_KEY`              | Contents of the corresponding `.p8` file                                          |
| `PMAI_UPDATER_PUBLIC_KEY`            | Public key generated by the Tauri signer                                          |
| `TAURI_SIGNING_PRIVATE_KEY`          | Contents of the Tauri signer private key file                                     |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | Signer key password; empty only for an unencrypted key                            |
| `RELEASES_TOKEN`                     | Fine-grained token with Contents read/write on the public releases repository     |

The default Actions token cannot publish to a different repository. Limit
`RELEASES_TOKEN` to the downloads repository. Keep key backups outside Git.
Generate the updater key once, using an absolute path outside the checkout:

```sh
cd apps/desktop
deno task tauri signer generate -w /secure/location/prompt-waypoint.key
```

Use the generated public key file's contents for `PMAI_UPDATER_PUBLIC_KEY`. Keep
the same key across releases: installed apps trust that key. Developer ID
signing and updater signing serve different purposes and both are required.

Apple's API key here notarizes a direct download; this does not submit the app
to the App Store. Use a **Developer ID Application** certificate, not Apple
Distribution. The workflow imports it into a temporary keychain, signs both
architectures' helper executables with the V8 JIT entitlement, signs the outer
app with hardened runtime, notarizes/staples it, then creates and notarizes the
DMG. It signs the final updater archive and verifies it against the public key
before publication.

## Publish a version

1. Update `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml`, `package.json`
   and the Cargo lockfile to the same stable semantic version.
2. Update `RELEASE_NOTES.md`, commit the changes, then push tag `macos-v0.2.0`
   (replace with the new version). Alternatively run **Release macOS** manually
   on the intended commit. A tag must match the app version.
3. GitHub Actions builds a universal app and uploads these files to a draft:
   - `Prompt-Waypoint.dmg`
   - `Prompt-Waypoint.app.tar.gz`
   - `Prompt-Waypoint.app.tar.gz.sig`
   - `latest.json`
4. Only after all assets are present does it publish and mark the release
   Latest. Failed draft uploads can be retried. Published versions cannot be
   overwritten; bump the version for a fix. Older versions cannot replace
   Latest.

Do not put unrelated releases in the downloads repository: GitHub's `latest`
redirect is shared by every release there.

## Local build and checks

Requires Deno **2.9.6**, Rust with `aarch64-apple-darwin` and
`x86_64-apple-darwin` targets, and Apple's build tools. The agent build uses an
isolated temporary workspace and locked dependencies; it does not package other
applications or their build outputs.

```sh
deno task --cwd apps/desktop macos:build
deno run --allow-read --allow-write --allow-env --allow-net --allow-run apps/desktop/scripts/smoke-bundled-agent.ts
```

This creates an **unsigned development app**, not a downloadable release. To
produce release artifacts locally, install `minisign`, import the Developer ID
certificate, and supply the signing variables listed above (`APPLE_API_KEY_PATH`
points to the local `.p8`; `APPLE_API_PRIVATE_KEY` and certificate import
secrets are only needed by CI). `PMAI_UPDATER_PUBLIC_KEY` must already be set
while building, because it is embedded in the native executable.

```sh
deno task --cwd apps/desktop macos:release RELEASE_NOTES.md
```

Outputs go to `src-tauri/target/macos-release/`. Never publish the unsigned
build. Before the first public release, check installation from a quarantined
DMG, provider discovery/run/stop, login launch and an actual signed N → N+1
update on Apple Silicon and Intel. Automated checks do not replace those
Gatekeeper and native UI checks.

## Moving from TestFlight

Quit and remove the TestFlight app, then install the direct download. Existing
standalone-agent data in `~/.pmai-agent` is reused. Desktop drafts/settings from
the old App Sandbox container are **not automatically migrated**; preserve them
before removal and configure the direct app again. The old App Store Connect
record/build is historical; repository changes do not remove it from Apple's
servers.
